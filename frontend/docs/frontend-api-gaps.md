# 前端基础接口对接情况与缺口

## 已对接（真实可用）

| 能力 | 接口 | 说明 |
|------|------|------|
| 登录 | `POST /api/v1/auth/login` | api 模式下走现有 `fetchLogin`；后端为服务端会话（兼容 Bearer 携带会话标识），不存在 refresh-token 接口 |
| 当前用户 | `GET /api/v1/auth/getUserInfo` | api 模式下走现有 `fetchGetUserInfo` |
| 退出 | 登出逻辑沿用 Soybean auth store | 会话过期按 logout codes 处理 |
| 请求封装 | `src/service/request` | 统一响应 `ApiResponse` 成功码 `0000`；已移除 apifox 演示请求头与远程 Mock 基址 |

> 演示模式（`VITE_BID_DATA_MODE=demo`，默认）下登录与业务数据全部走本地 fixtures，
> 不向真实后端发送演示写请求。

## 待接入（api 模式下明确显示「未接入」，不静默回退 Demo）

| 业务能力 | 期望接口（以后端实际 Controller 为准） | 备注 |
|----------|--------------------------------------|------|
| 项目列表/详情 | 暂无对应业务表接口 | 后端当前只有 assets 体系 |
| 解析文件列表/状态 | 任务查询接口（V4 任务+Outbox 落地后） | 前端已有任务状态数据接口占位 |
| 结构化条款/版式/字体/布局 | 解析结果查询接口 | 依赖解析核心 |
| 开始解析/开始审查/智能生成/修订 | Dify 工作流触发接口 | 本轮不接入、不伪造执行 |
| 审查问题/报告/一致性校验 | 审查结果查询接口 | 依赖审查核心 |
| 草稿保存 | 生成草稿接口 | 演示态保存在 localStorage |
| 模板/素材列表与写入 | `/api/v1/assets`（已存在创建/查询/版本/发布/关系） | 需按 Controller/DTO 做字段映射；列表过滤接口是否齐备待核对 |
| 文件上传/下载 | 后端文件接口（presign） | 前端不持有 MinIO 密钥 |

## 已知字段差异

- 后端统一响应为 `code/message/msg/data/trace_id`（msg 兼容现有请求封装）；
  分页真实响应字段以后端 DTO 为准，前端不假定所有接口都是 `records/total`。
- 后端登录返回会话标识，不是 JWT，前端不自行解码。
- 演示统计（中标率、评分点覆盖率、抽取置信度等）在界面上均标注「演示值」，
  接入真实接口后必须替换为真实指标或「未提供」。
